## 维护方式

修改职责边界、配置语义、状态恢复或适配依赖时，同步修改对应设计；只改默认颜色或补一个调用示例时，不重复抄写实现。说明应回答为什么、模块隐藏了什么复杂性、哪些条件必须保持，以及何时需要重新评估方案。

源码链接用于定位拥有设计决策的模块，测试链接用于定位回归入口，不代表本次已执行或已通过。具体检查结果写在 PR／CI 中。历史方案和逐轮验证可从 Git 与对应 PR 查阅，不另建“最终版”副本。

现状与维护约束分别表达：描述当前行为时以源码为准；提出升级或新增能力的条件时说明触发原因，不把尚未实现的能力写成保证。公共合并、主题、Tooltip 和分类缩放规则只在整体架构展开，组件文档保留必要的差异与链接。
