# 图表架构与 API 审查（2026-11-26）

## 结论

词云采用“原生 graph 绘制 + 自定义测量/布局 + 公共 Vue 渲染”的方案合理，适合当前水平文字、矩形标签和圆形气泡的产品范围。它复用了标签、状态、图例和命中机制，调用方无需理解坐标转换或维护重复的交互状态。纯布局可独立测试、结果确定、候选次数有限；这些比引入新颖算法更有助于长期维护。

本轮修复了空间网格可能无界分配/循环、稀疏尺寸区间漏校验、大数组权重展开超出引擎参数上限、减少动态效果恢复丢失系列筛选状态四个问题，随后通过强化重排测试修复了原生选择索引缓存残留。新增实际组件和双 Vue 打包消费回归，并对词云设置自动覆盖率门槛。它仍是同步 CPU 布局，不适用于无限量实时数据或任意轮廓的像素级填充；当前没有依据为了“先进”迁移到 Worker、WebGL 或力导向模拟。

## 方案取舍

| 方案                     | 收益                                                           | 成本及结论                                                                      |
| ------------------------ | -------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 原生 graph + 专属 layout | 原生 label、categories、状态、事件、选择与动画；value 保持标量 | 依赖原生视觉阶段顺序、view 坐标与 Symbol 结构；当前采用，兼容矩阵保护适配契约   |
| custom 系列完整自绘      | 完全控制元素结构、布局和持续动画                               | 需重新承担分类、选择、标签状态、命中和更新动画；现阶段没有足够收益支持替换      |
| 独立词云扩展或异步布局   | 可发展字形掩码、任意轮廓、后台计算                             | 增加依赖/发布兼容和异步取消、字体传递、过期结果处理；出现相应业务需求后单独设计 |

## 模块边界与质量

| 模块                                    | 隐藏的复杂性                                                   | 审查结果与约束                                                                                           |
| --------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `types.ts` / `createWordCloudOption.ts` | 配置校验、默认值、不可变数据、稳定 id、样式优先级、原生 option | API 集中、无需业务传坐标；`__ixWordCloud` 是内部标记，不作为扩展接口                                     |
| `layout.ts`                             | 碰撞、空间索引、尺寸域和确定性放置                             | 无 Vue/ECharts 依赖，适合边界与性质测试；极大网格回退扫描，每节点螺旋候选最多 5000，圆形还有有限切线候选 |
| `wordCloudLayout.ts`                    | 原生字体测量、状态几何、visual 时序、坐标换算、缓存            | 保持为一个适配边界，避免把原生内部知识散到通用 shared；目前无需按执行步骤继续拆小文件                    |
| `motion.ts`                             | 稳定轨迹、像素换算、暂停恢复、环境监听和 view 清理             | 隔离漂浮与父节点原生布局；SSR 不启动，过滤状态在减少动态效果切换后继续保留                               |
| `selection.ts`                          | 显式 selected 与用户选择的协调                                 | 按稳定 id 恢复，删项清除记录；身份或显式选择变化重建选项以清除原生缓存；同名项沿用原生选择联动限制       |
| `WordCloud.ts`                          | 公共主题/渲染接入、字体加载和实例就绪                          | 通过共享渲染层保留控制配置语义；字体监听在卸载时释放                                                     |

健壮性：零值有效，无效词条保留原始索引并跳过；非法布局配置清空生成系列、非法 motion 仅关闭漂浮。无法放置的项不绘制、不命中，不偷偷压缩显式尺寸。校验不承担任意 JSON schema 解析。空间索引有限分配，极大 gap/几何不会让整数递增失去精度而卡死；数据总量仍决定总 CPU 和内存成本，建议业务预选 TOP 项。

可扩展性：新 shape 应同时增加尺寸策略、碰撞规则、测量适配及契约测试，不能仅扩展字符串联合。新的运动模式应保留同一个最大位移契约，避免动画轨迹与预留边界相互泄漏。确有多组件消费者后再抽 shared，不把词云特有的 6px 交叠与两邻居规则变成全局配置框架。

可维护性：使用原生语义和公共深层合并（数组整体替换），比复制一套 label、tooltip、事件和状态 API 更简单。`sizeRange` 在不同 shape 下分别代表字号、建议最小高度和直径，减少配置数量但需要显式文档；未来不应继续把不相干维度塞入该字段。

可调试性：警告统一带组件前缀；非法 symbolSize 报原始索引。排错按“输入校验 → 实际容器与边距 → 状态标签几何 → motion 空间 → 原生配置覆盖”定位。通过公共 `getEChartsInstance()`、`getOption()`、`resize()` 诊断，私有标记和原生模型不是稳定业务 API。暂不增加每帧日志或统计事件。

可测试性：纯几何验证确定性、边界、间距、交叠和运动包络；原生 SVG 集成验证状态、回调标量、字体与分类；Vue 测试验证主题继承、选择和资源释放；真实 tarball 消费验证声明、入口和 Vue/ECharts 兼容。专项门槛为语句 99%、分支 97%、函数 100%、行 100%，按词云目录聚合；完整仓库及合并覆盖率另行报告，不能用总覆盖率掩盖新增组件缺口。

## 跨组件实现与 API 一致性

审查了 Bar、Line/Area、Pie、Radar、Gauge、Bullet、LiquidFill、Map 与 WordCloud 的组件入口、选项生成/适配与共享模块；这不是逐条证明所有历史功能正确的形式化审计。

| 组件组                     | 实现分工                                                                          | API 判断                                                                                   |
| -------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Bar / Line / Pie           | 保留旧原生包装路径，另有分类或自动布局路径；共享 render、主题、选项更新及交互恢复 | 两种模式承担兼容性，不能强制重写为同一个生成器；模式选择应继续以明确业务输入为准           |
| Radar / Gauge / LiquidFill | 薄 Vue 入口 + 纯 option 生成 + `usePlotRender`                                    | 简单入口隐藏默认配置，职责清楚；保留原生字段与少量业务配置                                 |
| Bullet                     | 原生 bar 承担实际值，专属布局/图形承担范围、目标、缺失态                          | 与词云“原生承载 + 专属适配”方向一致；有轴图表与无轴词云无需强行统一 dataZoom 或尺寸字段    |
| Map                        | 原生 geo/series 组合，独立数据生成和校验工具                                      | 无单一 mode 配置，符合节点/路线/区域组合；几何由应用管理，避免打包资产与组件耦合           |
| WordCloud                  | 原生 graph + 确定布局 + 可选运动                                                  | `shape`、`sizeRange`、`gap`、`overlap`、`motion` 是局部扩展，其他配置保留 graph 和公共语义 |

公共一致性成立于以下契约：`withChartProps` 和 `*ChartPublicProps` 承担 Vue/声明适配；`theme`/`CHART_THEME_TOKEN` 控制原生实例，`plotTheme`/`PLOT_THEME_TOKEN` 控制视觉默认值；`loading`、默认插槽、原生事件、`getEChartsInstance()` 沿用 core；原生 `series` 整体替换生成系列，数组不按索引混合，原始业务数据不被生成器修改。

需要保留的差异：Bar/Line 的组件 token 属于旧 API；新图表没有为了形式统一重复引入每图 token。`data` 的标量数组、对象数组和 Map 独立 helper 输入对应不同领域模型，不应合成一个弱类型联合。缺失值在有轴图表中有显示含义，词云则必须跳过非法权重，不能把缺失强制解释为零。

现有技术债：部分旧入口保留 `any`/`@ts-ignore`，公共 `AdditionalChartOption` 也允许原生透传。因此“未支持字段在类型上必然报错”并不成立；`KnownProps` 改善调用侧提示但不是严格 schema。词云类型省略 dataset/grid/dataZoom，仍需文档明确使用范围。整体收紧透传、统一 nullable title 的命名类型或迁移旧 token，应单独评估兼容性，不在词云 PR 中顺带破坏现有调用。

更新策略补充：仅词云启用 `resetOnDataIdentityChange`。共享 updater 比较 id/name/selected 快照，发生变化时使用原生 notMerge 重建；数值变化继续合并。该策略牺牲重排时的元素连续过渡，换取正确的原始索引与显式选择更新，避免修改 ECharts 私有选择缓存。原生 graph 选择以名称为键，同名词条仍会联动，稳定 id 仅管理数据与跨重建恢复；独立选择需不同名称。

## 保留风险与后续触发条件

1. 持续动画依赖 graph Symbol 首个子路径、Animator 与 view remove/dispose。升级 ECharts 时必须跑声明/运行时矩阵和生命周期回归；若原生结构变化，修改适配边界，不能让业务依赖这些字段。
2. 同步搜索是有限的，但总耗时随数据量、字体复杂度和拥挤度增加。先限制业务输入并测量；只有真实大数据卡顿证据才引入可取消异步布局。
3. 无 overlap 时预留完整运动空间；rect overlap 模式仅保留容器边界，静态交叠约束不保证运动中仍成立。原生更新过渡、主动 emphasis.scale、labelLayout 位移和旋转超出避让保证。
4. 字体测量依赖环境，确定性仅针对同字体/尺寸环境；直接 option 消费者自行在字体完成后 resize。系统减少动态效果关闭漂浮，但本轮没有承诺同时关闭 ECharts 原生入场动画。
5. 自动覆盖率是回归约束，不能代替视觉审查、性能测量或 CI。当前实际执行结果与未执行范围统一登记在 [验证记录](word-cloud-validation.md)。
